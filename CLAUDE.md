# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MSPM0G3507 two-wheel balance-car (BDC) firmware for TI electronic design competition. Built on **TI MSPM0 SDK 2.10.00.04** + **FreeRTOS 11.1.0** + **ARM GCC 15.2.1** (Cortex-M0+, `armv6-m`). Hardware init code is auto-generated by **SysConfig 1.27.0** (`SysConfig/ti_msp_dl_config.c/h`).

## Build / Flash / Debug

| Task | Command |
|------|---------|
| Configure | `Ctrl+Shift+P → CMake: Configure` (pick the GCC preset) |
| Build | `F7` or `cmake --build build` |
| Clean rebuild | `cmake --build build --clean-first` |
| Flash (JLink, **recommended**) | `Flash/JLink_flash.bat` |
| Flash (OpenOCD) | `Flash/OpenOCD_flash.bat` |
| Debug | `F5` (Cortex-Debug extension — CMSIS-DAP or JLink) |

Build outputs: `build/<project_name>.elf`. The ELF name matches `CMakeLists.txt` `project()` name.

**Key build files:**
- [`mspm0g350x_base.cmake`](mspm0g350x_base.cmake) — toolchain, SDK path (`MSPM0_SDK_PATH`), `-mcpu=cortex-m0plus -march=armv6-m -mthumb -mfloat-abi=soft`, linker scripts. **Edit SDK path here for your install.**
- [`CMakePresets.json`](CMakePresets.json) — compiler paths (hardcoded), build type, Ninja generator, `CMAKE_EXPORT_COMPILE_COMMANDS=ON`
- [`CMakeLists.txt`](CMakeLists.txt) — globs `User/**/*.c/*.cpp` and `FreeRTOS/*.c` automatically. New source files under `User/` are auto-discovered.

**Important flash caveats:**
- OpenOCD + MSPM0 can lock the chip. JLink is preferred. If you get `AP write error, reset will not halt`, the chip is locked — use `mspm0_mass_erase` (requires nRST pin connected on DAPLink). The flash scripts now use the `program` command (simpler than the old multi-step sequence).
- Debug sessions use F5 only. The user cannot flash via debug — each test cycle is **F7 (build) + F5 (debug)**, not flash.
- Don't set multiple breakpoints; single-breakpoint debugging only.

## Architecture

**5-layer design** under `User/`, dependency flows downward:

```
User/App/         → main.cpp, FreeRTOS tasks, test tasks
User/Device/      → Motor(PID+PWM+QEI), TiGyro, IicOled, IicTrack
User/Protocol/    → UART frame protocol, CAN motor protocol
User/Algorithm/   → PID (position-form, integral separation)
User/Bsp/         → BspUart, BspPwm, BspQei, BspCan, BspI2c, BspGpio, BspKey
User/Service/     → FreeRTOSConfig.h, sysmem.c, user_system (format())
User/Module/      → (reserved)
```

Dependency: **App → Device/Protocol/Module → Bsp → TI DriverLib**

### Initialization order (in `main()`)

1. `SYSCFG_DL_init()` — hardware (auto-generated, **never edit**)
2. `bsp_init()` — bind BSP wrappers to hardware instances
3. `protocol_init()` — start UART frame-parsing FreeRTOS task
4. `device_init()` — bind device drivers to BSP objects (e.g. Motor→PWM+QEI)
5. `xTaskCreate(...)` ×9 — create FreeRTOS tasks
6. `vTaskStartScheduler()` — never returns

### Production FreeRTOS tasks

| Task | Stack | Prio | Period | Role |
|------|-------|------|--------|------|
| `motor_task` | 768 | 6 | 2ms | Left/right motor speed PID update |
| `line_task` | 1024 | 6 | 2ms | 12-sensor weighted-centroid line-follow PID |
| `motor_print_task` | 512 | 5 | 2ms | UART4 debug telemetry |
| `oled_task` | 256 | 5 | 200ms | OLED display (track bits + gyro angles) |
| `gpio_task` | 256 | 4 | 50ms | Button debounce, LED, buzzer |
| `gyro_task` | 512 | 4 | blocking | Parse gyro attitude frames from UART3 |
| `track_task` | 256 | 4 | 10ms | Read PCA9555 track sensor via I2C1 |
| `cpu_monitor_task` | 256 | 1 | 500ms | CPU idle % via runtime stats |

### Test tasks

Test tasks live in `User/App/test/` (one file per peripheral). Enable them by uncommenting `xTaskCreate()` calls in [`User/App/main.cpp`](User/App/main.cpp). Declarations are in [`User/App/test.hpp`](User/App/test.hpp).

### Key patterns

- **BSP classes = runtime ops only.** Hardware register config is done by SysConfig's `SYSCFG_DL_xxx_init()`. BSP `.init()` just binds to pre-configured instances.
- **Global instances** declared `extern` in `bsp_cfg.hpp`/`device_cfg.hpp`, defined in matching `.cpp`.
- **`BspUart<BufSize>`** uses FreeRTOS Stream Buffers: RX ISR → StreamBuffer, TX DMA ← StreamBuffer. `ProtocolUartUser` wraps one UART with a dedicated parsing task using frame format `[AA][55][CMD][LEN][DATA][SUM][0D]`.
- **`Motor`** closed-loop control: QEI encoder → speed calc → PID → H-bridge PWM (4-ch TIMA0, forward/reverse channels). `update()` must be called at fixed period.
- **`Pid`** class: position-form with integral separation (|error| < 60% of target), zero-reset on large errors (>100% target), output + integral clamping.
- **Line-following**: 12-sensor weighted centroid → PID → differential motor correction. Full line loss (>50 ticks) stops motors and clears PID.

### SysConfig

File: `SysConfig/MSPM0_FreeRTOS_BDC_Core.syscfg`. Saving regenerates `ti_msp_dl_config.c/h`, `device_linker.lds`, `device.opt`. **Never hand-edit generated files.**

### FreeRTOS config highlights

[`User/Service/FreeRTOSConfig.h`](User/Service/FreeRTOSConfig.h): 80 MHz, 1 kHz tick, preemptive, 8 priorities, heap_4 (16 KB), runtime stats via tick hook, TrustZone/MPU configured but unused (Cortex-M0+).

## Code Style

See [`docs/编码风格.md`](docs/编码风格.md) for the full standard. Key rules:
- **Types**: PascalCase (`MotorDevice`, `Pid`)
- **Functions/variables**: `snake_case` (`motor_update()`, `max_speed`)
- **Macros**: `UPPER_CASE` (`MOTOR_MAX_RPM`)
- **Class members**: `_prefix` (`_speed_pid`, `_motor_id`)
- **Braces**: Allman style (brace on its own line), 2-space indent
- C++ headers use `.hpp`, C headers use `.h`
