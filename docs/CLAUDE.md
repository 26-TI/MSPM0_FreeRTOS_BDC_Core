# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MSPM0G3507 motor-control mainboard firmware for TI electronic design competition. Built on TI MSPM0 SDK 2.10.00.04 + FreeRTOS 11.1.0 + ARM GCC cross-compiler. SysConfig 1.27.0 generates hardware init code (`ti_msp_dl_config.c/h`).

## Build / Flash / Debug

| Task | Command / Shortcut |
|------|-------------------|
| Configure CMake | `Ctrl+Shift+P → CMake: Configure` (pick the arm-none-eabi preset) |
| Build | `F7` or `cmake --build build` |
| Clean rebuild | `Ctrl+Shift+P → CMake: Clean Rebuild` or `cmake --build build --clean-first` |
| Flash (JLink, recommended) | `Flash/JLink_flash.bat` (Win) / `Flash/JLink_flash.sh` (Linux) |
| Flash (OpenOCD) | `Flash/OpenOCD_flash.bat` (Win) / `Flash/OpenOCD_flash.sh` (Linux) |
| Debug | `F5` (Cortex-Debug extension, JLink or CMSIS-DAP via OpenOCD) |

Build outputs land in `build/`. The elf is `build/<project_name>.elf`.

**Prerequisites**: `arm-none-eabi-gcc` on PATH, CMake ≥ 3.27, Ninja, TI MSPM0 SDK installed.

### Build Config Files

- **`mspm0g350x_base.cmake`** — cross-compiler toolchain, SDK path, compile/link flags, auto-discovers SDK sources. **Edit `MSPM0_SDK_PATH` here** to match your local SDK install.
- **`CMakePresets.json`** — CMake preset (generator + compiler paths). Must be created from `CMakePresets.json.txt` template.
- **`CMakeLists.txt`** — top-level: includes the base cmake file, then globs `User/**/*.c/*.cpp` automatically. The `project()` name must match the root folder name. New `.c/.cpp` files under `User/` are auto-discovered.

## Architecture

The project uses a **5-layer architecture** under `User/`:

```
User/
├── App/         Application — main.cpp, test task entries
├── Bsp/         Board Support Package — UART/PWM/QEI/I2C/SPI/CAN/GPIO/Key wrappers
├── Device/      Device drivers — motors (PID + QEI), IMU (gyro), OLED, track sensor
├── Protocol/    Communication protocol — frame-parsing task with checksum, CAN motor proto
├── Algorithm/   Algorithms — PID, future: filters, trajectory
├── Service/     FreeRTOSConfig.h, sysmem
└── Module/      (reserved) high-level business modules
```

Dependency flows downward: App → Device/Protocol/Module → Bsp → TI DriverLib.

### Initialization Order

1. `SYSCFG_DL_init()` — hardware init (clocks, pins, peripherals) — **auto-generated by SysConfig, do not edit**
2. `bsp_init()` in [bsp_cfg.cpp](User/Bsp/bsp_cfg.cpp) — binds BSP driver objects to hardware instances (UARTx_INST, etc.)
3. `device_init()` in [device_cfg.cpp](User/Device/device_cfg.cpp) — binds device drivers to BSP objects (e.g. motor → pwm + qei)
4. `xTaskCreate(...)` — creates FreeRTOS tasks
5. `vTaskStartScheduler()` — starts the scheduler, never returns

### Key Patterns

- **BSP classes encapsulate runtime operations only** — hardware register configuration is handled by SysConfig-generated `SYSCFG_DL_xxx_init()`. Bsp classes do `.init({HW_INST, ...})` to bind to the pre-configured peripheral.
- **Global instances** are declared in `bsp_cfg.hpp`/`device_cfg.hpp` as `extern`, defined in the corresponding `.cpp`.
- **Test tasks** live in `User/App/test/` — one file per peripheral. Enable/disable them by commenting `xTaskCreate()` calls in [main.cpp](User/App/main.cpp). All test task signatures are declared in [test.hpp](User/App/test.hpp).
- **`BspUart<BufSize>`** uses FreeRTOS Stream Buffers for RX/TX decoupling: RX via FIFO+interrupt feeding a stream buffer; TX via DMA from a stream buffer. `ProtocolUartUser` wraps one UART with a dedicated FreeRTOS parsing task using a frame protocol (0xAA 0x55 CMD LEN DATA... SUM 0x0D).
- **`Motor`** does closed-loop speed control: QEI encoder → speed calculation → PID → H-bridge PWM (forward/reverse channels). `update()` must be called at a fixed period from a timer ISR or task.
- **`Pid`** is position-form with integral separation and startup compensation.

### SysConfig

The file `SysConfig/MSPM0_FreeRTOS_Ctrl.syscfg` defines all pin muxing and peripheral configurations. Saving it auto-regenerates `SysConfig/ti_msp_dl_config.c` and `SysConfig/ti_msp_dl_config.h`. **Never edit those generated files by hand.** Pin definitions (like `LED_PIN_Led_PIN`, `KEY_PIN_1_PIN`) come from the generated header and are used throughout BSP init.

### FreeRTOS Config

[FreeRTOSConfig.h](User/Service/FreeRTOSConfig.h): 80 MHz CPU clock, 1 kHz tick, preemptive scheduling, 8 priority levels, heap_4 (8 KB), software timers enabled, task notifications/mutexes/recursive mutexes/counting semaphores enabled. Stack overflow detection and runtime stats are disabled. TrustZone and MPU are configured but unused (Cortex-M0+ has no TrustZone).

### Pin Assignments

See README section 5.2 for the full pinout table. Key mappings:
- UART1 (PB7/PB6): gyro IMU
- UART2 (PB18/PB17): debug/protocol output at 115200 8N1
- I2C0 (PA0/PA1): OLED (0x3C)
- I2C1 (PA29/PA30): track sensor PCA9555
- CAN0 (PA26/PA27): 1 Mbps standard frames
- PWM TIMA0 (PB8/PB9): 80 MHz, period=10000
- PWM TIMG0 (PB10/PB11): 40 MHz, period=10000

### Code Style

`.clang-format` config based on LLVM with Allman braces, 2-space indent, right-aligned pointers (`int *p`), no column limit. clangd is configured with inlay hints enabled; `-Wimplicit-function-declaration` is suppressed. CMake exports `compile_commands.json` for clangd.
